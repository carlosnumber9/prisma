# Prisma portal implementation

## Architecture and delivery

The first portal uses Next 16.4.0, React 19.3.0 and App Router, with statically prerendered pages and CSS Modules. It keeps the normal Next output compatible with future Vercel hosting; it is not an HTML export. There is no content API, database, model service, comparator or correction form.

Node 24.x and npm 10.8.2 remain required. TypeScript 7.0.2 supplies `tsc`; the `typescript` npm alias points to the official TypeScript 6 API compatibility package needed by ESLint. [Microsoft documents this coexistence](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/). Application code has a strict configuration separate from checked JavaScript tooling. Dependencies are pinned and installed without forced peer resolution.

WGSL tooling is pinned to `vgpu` 0.6.0 and matching `@vgpu/wgsl`. The official Turbopack rule prepares and minifies shader imports at build time, and `src/wgsl-env.d.ts` declares their TypeScript module shape. Build-time reflection does not replace device-backed validation: use `npx vgpu check <shader.wgsl> --require-validation` on a compatible development machine.

The content adapter explicitly imports only the four files under `content/generated`. The reader accepts schema v3, checks envelope consistency and resolves stable IDs. The generator remains the authority for full input validation. Build runs `content:check` first and fails on invalid or stale content without regenerating it. Incorporating approved content later requires an editorial generation and a new build.

## Routes and editorial states

The catalogue initially has five formations and eight areas: 336 pages across six locale-prefixed versions of home, party/topic directories, party pages and synthesis pages. Dynamic routes enumerate the generated catalogue with `generateStaticParams` and disallow unknown IDs. A dedicated 404 provides a return path.

Home opens with the existing title above an animated glass prism and a centred explanatory subtitle below it, with area browsing after the first viewport. Below 1024 pixels wide, one “Lista de partidos” link to `/parties` follows the areas. Wider screens replace that button with a mirrored “Por partidos” column linking to each formation. The list subtitle and catalogue-wide availability panel are omitted; individual summary pages retain explicit availability. Area pages list formation links and review states; they do not implement comparison. Formation pages omit the official website link when it is null. The catalogue's limits and [provenance](catalogue-provenance.md) are explicit.

- `pending`: “Resumen todavía no disponible”, without inferring that a formation lacks proposals or has not published a programme.
- `partial`: approved points, citations and the explicit partial-review notice.
- `complete`: reviewed points, revision and review date. An empty complete review says no proposals were identified in the reviewed corpus and retains its reviewed sources.

Points preserve their IDs as shareable anchors. Native disclosure controls expose source quotations without client-side state. PDF references retain physical and optional printed page numbers; HTML references use only actual source anchors. Dates use the selected language and UTC, with explicit Aranese month names independent of runtime ICU support. Sources link to official URLs; local originals, extraction and review records are never copied into web assets.

## Internationalization

Supported locales are `es`, `ca`, `gl`, `eu`, `oc` and `en`. `ca` is shared Catalan/Valencian; `oc` contains Aranese translations. Typed dictionaries cover interface strings, accessibility labels and metadata; topic labels and approved point titles/texts come from schema-v3 locale maps. No internationalization package or runtime translation service is used.

All catalogue pages live below `[locale]` and remain prerendered. Proxy handles neutral entries before rendering, using a valid `prisma-locale` cookie, then the first supported browser preference by quality/order, then `es`. Regional tags such as `ca-ES-valencia` map to the supported base language. The browser header represents browser preferences, not direct OS access. Explicit locale URLs bypass negotiation and never update the cookie. Neutral redirects use HTTP 307, retain queries, and send `Cache-Control: private, no-store` with `Vary: Accept-Language, Cookie`. Framework files, public assets, API paths, robots and sitemap bypass negotiation.

The custom navbar language picker labels each option in its own language, retains path/query/point fragment and saves manual preference for one year with path `/`, `SameSite=Lax` and `Secure` on HTTPS. It performs a full navigation so document language and root layout update together. Browser storage restrictions may prevent persistence; the selected locale URL still works. At widths up to 768 pixels, the selector appears inside the collapsed navigation panel.

Each page has its locale on `<html>`. Local not-found boundaries use root locale context; the global unmatched fallback is Spanish with its complete content wrapped in `lang="es"`. Next supplies that fallback's outer HTML document, which has no language attribute. Original quotation/title/section text uses `lang=""` because source-language metadata is unknown, preventing false inheritance from the interface language. Unknown catalogue IDs remain unavailable for on-demand rendering.

When `SITE_URL` is configured, each localized page has a self canonical, six `hreflang` alternatives and a neutral `x-default` URL. The sitemap lists each indexable locale version; pending syntheses remain excluded. Without a configured origin no canonical/alternates or sitemap URLs are invented. UI and topic translations are agent proposals prepared for maintainer review; automated checks do not establish linguistic quality. No political prose was added.

The isolated `LanguageSelect` client component replaces the native select with a button and a six-option listbox. The visible language label is removed; the trigger retains a localized accessible name including the current language. Its background is transparent, with a soft grey (`#c7cdd1`) bottom border and a single CSS chevron pointing down when closed. Opening rotates the same chevron clockwise by 180 degrees over 100 milliseconds with GSAP `power1.inOut`, matching the complete option cascade; closing reverses that rotation without changing its position. Reduced motion changes its orientation immediately. Each option uses the mobile panel's `#f8fafb` background and the same soft border colour. Options enter in catalogue order with a 50-millisecond upward-offset-to-rest fade, staggered by 10 milliseconds, resembling dealt cards and completing the six-option sequence in 100 milliseconds. A paused GSAP timeline owns both option motion and chevron rotation: opening calls `play()`, closing calls `reverse()` from the current playhead, reversing order and easing so the last option leaves first. The list remains visible and in layout until `onReverseComplete` hides it; `inert` and `aria-hidden` disable interaction and screen-reader exposure immediately on closure. Reopening during exit continues the same timeline without a jump. GSAP owns the list’s `hidden` property after hydration, and its context restores styles and kills the timeline on unmount. Reduced motion and live preference changes seek directly to the appropriate endpoint and hide a closed list immediately. Desktop positions the list beneath the trigger; mobile keeps it in the panel's scrollable flow.

The inner polygon offsets each slanted edge by the border’s normal distance, preserving the outline around the full silhouette. Keyboard focus thickens that outline to three dark pixels. Option labels are centred. ## Shared halftone background

The shared `Shell` renders a decorative `HalftoneBackground` client leaf below all navigation and reading content. Its Canvas 2D renderer samples a continuous wave field on a fixed grid: each point grows near a crest and shrinks to zero in a trough. Two curved wave families propagate from different origins, with periods of 9 and 12 seconds. Neighbouring points respond successively, so dotted regions travel into previously empty areas instead of brightening a permanently visible texture. The field covers the whole document, including below the first viewport, and repeats continuously over 36 seconds without resetting its clock.

Dot colour remains `#64717b` and layer opacity remains the original `0.24`; there is no additive contrast layer. Maximum radius remains 2.15 units on a 20-unit grid. The animated field keeps the central reading area slightly quieter while allowing waves to cross it. Geometry, wave periods and the static fold field live in `src/lib/halftone.ts`. The shell's `--dot-texture-opacity` controls both renderers; `--dot-texture-min-width` defaults to `960px` and keeps the image and canvas scales aligned on narrow screens.

The original `public/dot-texture.svg` remains a CSS pseudo-element fallback. Its 1440-unit square tile repeats vertically, scaling to the shell width with the same 960-pixel minimum and horizontal cropping. `scripts/generate-dot-texture.mjs` now imports the shared static field; run `node scripts/generate-dot-texture.mjs` with Node 24 after changing that geometry. The generated SVG is unchanged by this animation delivery and is excluded from Prettier. Before hydration, with reduced motion, or without a usable 2D context, the original static texture stays visible.

The canvas initially matches the SVG, then blends its radii into the travelling field over 1.2 seconds. Only after a successful draw does it replace the SVG, avoiding two overlapping textures. Live reduced-motion changes restore the static fallback. The renderer caps updates at 24 fps and DPR at 1.5, suspends its loop while the document is hidden, and releases its frame, observers and listeners on unmount. The canvas buffer covers only the viewport; document coordinates and passive scroll measurements keep the grid anchored to the page without allocating a document-sized bitmap. Resize observation handles viewport and content changes.

The homepage shader paints an opaque background. The prism canvas, fallback poster and halftone layer therefore retain stacking levels `-3`, `-2` and `-1` inside the shell's isolated context. The texture remains visible with or without WebGPU and overlays the prism itself; it does not simulate refraction of the points through the glass. The decorative layer has no pointer interaction, accessible content or layout space.

Deterministic tests cover the initial fallback match, newly visible and disappearing regions throughout a long page, successive arrival at neighbouring cells, and continuous wave repetition. Standalone snapshots of the actual wave field were inspected at several times. Browser verification of the full composition, reading contrast, scrolling and device performance remains pending; no app server was started for this change.
