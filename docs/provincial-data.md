# Provincial electoral data foundation

The [accepted Congress presence batch](../content/political-info/approved/congress-2026-provinces.json) covers 534 proclaimed candidatures in 52 constituencies for the general election of 29 November 2026. It preserves official formation denominations and citations to the BOE publications of 3 and 7 November. Candidate arrays remain empty and coverage explicitly excludes people and Senate lists. See the [review and agreement](../content/political-info/reviews/2026-11-20-congress-provinces.md).

`npm run provincial:generate` validates the scoped presence-only contract and writes `content/generated-provincial/congress.json`; `npm run provincial:check` checks it without writing. Both are included in the corresponding content commands. Validation checks field allowlists, unique records, references, dates, source/extraction hashes and quotation occurrence. The public projection contains only province IDs, formation IDs, labels and optional matching programme IDs. It does not expose source captures or create programmes or routes. Other political-reference batches still require their own validators.

[Province names and aliases](../content/geography/provinces.json) and the [IGN provenance record](../content/geography/metadata.json) accompany a frozen local polygon derivative. The derivative covers the 52 provincial constituencies, including islands, Ceuta and Melilla, and excludes non-provincial territory code 54. Attribution: Obra derivada de BDDAE CC-BY 4.0 ign.es. Topology-preserving simplification introduces a tolerance of a few tens of metres; manual province selection remains authoritative in the subsequent portal integration.

The pure location helpers have deterministic tests for provincial aliases, polygon holes, mainland/island/city/enclave positions, neighbouring-country rejection, Madrid fallback, optional session storage and manual-selection races. They accept injected location and storage boundaries and do not perform browser or network operations themselves. The implementation is split into this independently verifiable data foundation and the subsequent portal integration commit.
